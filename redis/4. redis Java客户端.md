# 介绍

## 客户端的作用

1. 维护和 Redis 的 TCP 连接（单连接、多连接、连接池）。
2. 将 Java 方法调用转换成 Redis 协议命令。
3. 解析 Redis 响应数据并返回 Java 对象。
4. 管理连接的生命周期（创建、关闭、复用）。

## 常见客户端

1. Jedis
以redis命令作为方法名称，学习简单，但是类中的方法比较臃肿，种类很多
但是线程不安全，多线程环境需要基于连接池使用

2. Lettuce
基于Netty实现，支持同步、异步、响应式编程，线程安全，支持redis哨兵模式、集群模式、管道模式（spring集成较好，推荐使用）

3. Redisson
基于redis实现的分布式、可伸缩的Java数据结构集合，包括map、queue、lock、semephore、Atomiclong
（原来这些数据结构是线程不安全或者仅支持单机场景，Redisson基于Redis让这些数据结构支持分布式，避免自己造轮子）

## Jedis和Lettuce的区别

> 这里重点在于连接池相关，其余的区别可以后续再深入了解

- **Jedis**
    
    - Jedis 默认就是**阻塞式、短连接或连接池模式**。
        
    - 如果你用 Jedis 的连接池（`JedisPool` 或 `JedisPooled`），就必须手动引入 `commons-pool2`，因为 Jedis 没有内置池实现，而是基于 `commons-pool2` 做的。
        
    - 如果你只用单连接模式（`new Jedis(host, port)`），可以不加 `commons-pool2`，但性能和并发支持会很差。
        
- **Lettuce**
    
    - Lettuce 默认是**基于 Netty 的异步非阻塞客户端**，本身没有强依赖连接池。
        
    - 如果需要连接池（比如和老版本 Spring Data Redis 配合，或需要阻塞式池化连接），则需要手动引入 `commons-pool2`。
        
    - 如果直接用 Lettuce 的异步 API 或反应式 API，不用连接池依赖。

如果你是**直接用 Jedis 或 Lettuce**（不通过 Spring Boot 自动配置），

- Jedis：要用池就手动加 `commons-pool2`。
    
- Lettuce：只有需要池化才加 `commons-pool2`，纯异步/反应式不用。

```java
    @AfterEach  
    public void tearDown(){  
        if(jedis!=null){  
            jedis.close();  
        }  
        System.out.println("关闭成功");  
    }  
}
```

### 连接池

#### 为什么Redis单线程而Jedis线程不安全

Redis本身是单线程执行操作，但是不禁止多个连接，一个Jedis实例代表一个和Redis的连接，多线程共享同一个Jedis实例的时候会不安全

如果你在多个线程中**共享一个 Jedis 实例**，这些线程可能**同时操作同一个 socket 连接**，会导致：
- 数据包混乱
- 命令错乱
- 阻塞卡死

因此推荐使用连接池，每一个线程使用单独的连接，同时复用连接，减少创建和删除的开销

#### 代码实现

连接池（工厂模式）
```java
package www.Twilight.testJedis;  
  
import redis.clients.jedis.Jedis;  
import redis.clients.jedis.JedisPool;  
import redis.clients.jedis.JedisPoolConfig;  
  
public class JedisConnectionFactory {  
    private static final JedisPool jedisPool;  
  
    static{  
        //配置连接池  
        JedisPoolConfig poolConfig = new JedisPoolConfig();  
        poolConfig.setMaxTotal(10);//最大连接数  
        poolConfig.setMaxIdle(8);//最大空闲连接数  
        poolConfig.setMinIdle(2);//最小空闲连接数  
        poolConfig.setMaxWaitMillis(1000);//最大等待时间  
  
        jedisPool=new JedisPool(poolConfig, "127.0.0.1", 6379);  
    }  
  
    public static Jedis getJedis(){  
        return jedisPool.getResource();  
    }  
}
```

后续获取：
```java
jedis=JedisConnectionFactory.getJedis();
```
关闭：
```java
jedis.close(); 
```
这里虽然和不使用连接池的方式相同，但是实际 close() 代码中会判断是否使用了连接池，如果使用了就是归还不是关闭（可以）

# SpringDataRedis

### 介绍

SpringData是Spring中数据操作模块，包含对于各种数据库的集成

SpringDataRedis
- 提供对不同redis客户端的集成
- 提供统一api
- 支持redis的发布订阅模型
- 支持哨兵、集群
- 支持基于Lettuce的响应式编程
- 支持基于JDK、JSON、字符串、Spring对象的数据序列化以及反序列化（原来都是基于字符串的存储，如果要存取一个对象，需要序列化反序列化）
- 支持基于Redis的JDKCollection实现

```xml
    <artifactId>spring-boot-starter-data-redis</artifactId>  
    <version>3.5.0</version>  
</dependency>  
<!-- 连接池 -->  
<dependency>  
    <groupId>org.apache.commons</groupId>  
    <artifactId>commons-pool2</artifactId>  
    <version>2.12.1</version>  
</dependency>
```

#### 配置

后续啊连接和配置相关，
这里直接使用springboot自动装配，只需要写xml文件即可，不需要和前面Jedis的一样自己写配置类连接

yaml文件示例如下，后续可以使用ai写问题不大
```yaml
spring:
	data:  
	  redis:  
	    host: 127.0.0.1  
	    port: 6379  
	    lettuce:  
	      pool:  
	        max-active: 8 
			max-idle: 8
	        min-idle: 0
	        max-wait: 100
```
