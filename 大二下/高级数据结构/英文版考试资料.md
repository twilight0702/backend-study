# Total Ordered Data Set

A **Total Ordered Data Set** is one in which every pair of elements can be compared with each other in a way that satisfies the mathematical definition of a "total order relationship". A total order relationship ensures that the data can be arranged in a defined order, thus supporting efficient retrieval, sorting, and other operations.

------

## I. Total Order Relationship (Total Order) Definition

Let there be a relation $R$ on the set $S$, and $R$ is said to be a **Total Order** relation on $S$ if the following four conditions are satisfied:

1. **Reflexive**:
For any $a \in S$, there are $a \leq a$
2. **Antisymmetric**:
If $a \leq b$ and $b \leq a$ then $a = b$
3. **Transitive**:
If $a \leq b$ and $b \leq c$, then $a \leq c$
4. **Totality or Comparability**:
For any $a, b \in S$, there must be $a \leq b$ or $b \leq a$.

------

## II. Meaning of Total Ordered Data Set

It is a class of data sets whose elements can satisfy the "full order" relationship described above, so that they can always be compared and uniquely ordered.

## III. Uses of the Total Ordered Data Set

Because the data can be sorted, many classical algorithms can be applied efficiently:

- **Binary Search**: time complexity $O(\log n)$
- **Sorting algorithms**: fast sort, merge sort, etc.
- **Ordered index structures**: e.g., B+ trees, red-black trees, etc. are constructed on the basis of the full-order property.

## Min-Max Heap

### What is Min-Max Heap?

Min-Max Heap is an array-based Complete Binary Tree that divides nodes into **Min layers** and **Max layers** according to their depth, as follows:

- **The root node is at the Min level (depth 0)**, indicating the minimum value of the whole tree.
- ** Its child is at the Max level (depth 1)**, indicating the subtree maximum.

- **grandchild node back to the Min level (depth 2)**, denoting the subtree minimum.

- So alternately.

That is to say:

- **Even layers (0, 2, 4, ...) are Min layers** that maintain the minimum value;

- **Odd layers (1, 3, 5, ...) are Max layers** that maintain the maximum value.

### Operation

| operations | time complexity | description |

| ------------- | ---------- | ---------------------- |

| `findMin()` | O(1) | root node |
| `findMax()` | O(1) | greater of two children of root |
| `insert(x)` | O(log n) | inserts and "floats" to the correct position |
| `deleteMin()` | O(log n) | delete root node and "sink" |
| `deleteMax()` | O(log n) | delete max node and "sink" |
#### 1. Node Hierarchy Determination

Given a node's subscript `i` (starting from 1) in an array with layers:

`level(i) = ⌊log₂(i)⌋'

Determines if it is at the Min level:

`is_min_level(i) = level(i) % 2 == 0`

#### 2. Insertion operations

- Inserts the new element into the end of the array;
- Determine which layer (Min or Max) it is on;
- Compare and float up to the correct position, following the rules of Min Heap or Max Heap, respectively.
#### 3. Delete operations (lookups are similar, except that there is no delete operation)
##### `deleteMin()`
- Delete the root node (subscript 1);
- Replace with the last element of the array;
- Sinks downward, maintaining the Min-Max Heap nature.

##### `deleteMax()`

- Find the larger of the two children (subscripts 2 and 3) of the root;

- Delete it and replace it with the last element;

- Downward "sinking".

## II. Core Ideas of the von Neumann System ##
### 1. Stored Program Control (**Stored Program Concept**)
Programs and data** are uniformly stored** in the main memory, which the computer reads and executes one by one in the order of instructions.

> Prior to this, early computers required manual wiring or control panel changes to "change programs", which was highly inefficient.

### 2. Sequential Instruction Execution (**Sequential Instruction Execution**)

The CPU reads instructions from memory **in order** and automatically jumps to the next instruction after executing one, unless it encounters a jump instruction (such as `goto` or `if-else`).

### 3. Data and instructions are stored in the same memory (**Unified Memory for Data and Instructions**)
Program instructions and data** share the same storage area**, which both simplifies the hardware structure and creates potential problems (e.g., program code can be modified, protection mechanisms are needed).
------

## III. Workflow: Instruction Cycle (**Instruction Cycle**)

The execution of an instruction usually consists of the following steps:
1. **Fetch**: Fetch the next instruction from memory (at the address specified by the program counter PC).
2. **Decode**: The controller analyzes the instruction to determine the operation to be performed and the operand position.

3. **Execute**: An operator or other unit performs an instruction operation.

4. **Store/Writeback**: Write the result back to memory or registers.

5. **Update Program Counter (PC)**: points to the address of the next instruction.

This process is called the **Fetch-Decode-Execute Cycle**.

## V. Strengths and limitations

### Pros:

- Simplified computer design structure for easy hardware implementation

- Unified memory model that allows programs to read and write data flexibly

- Become the infrastructure for the development of modern computers
### Limitations (also known as the "von Neumann Bottleneck" **Von Neumann Bottleneck**):
- **Instructions and data share the same memory bus**, resulting in limited read speeds (instructions and data cannot be read at the same time)

- Instructions are executed sequentially, not suitable for parallel processing tasks

- Cache misses can seriously slow down execution
------

## VI. Modern Development (Supplementary)

Although today's computer architectures are still based on von Neumann, many optimization techniques have been introduced in practice, for example:
- **Harvard Architecture**: instructions and data are stored and processed separately to alleviate bottlenecks

- **Pipelining**: multiple instruction stages processed in parallel to increase throughput rates

- **Cache Memory**: small cache inside the CPU to reduce access latency

# Amortized Analysis (AA)
Amortization analysis is a method used to analyze the average performance** of a **series of operations**.
Instead of focusing on the worst-case scenario of a single operation, it analyzes the **Amortized Cost** of an entire sequence of operations.

---

## I. Aggregate Method (Aggregate Method)
**Rationale:**

Assuming that \( n \) operations are performed at a total cost of \( T(n) \), the amortized cost of each operation is:

$$
\frac{T(n)}{n}
$$

That is, all operations are analyzed as a whole and the average cost is calculated.

**Features:**
- Simple and intuitive;
- Differences between operations are not taken into account;
- For situations where the cost of operation is not changing significantly or changes are predictable.
**Examples:**

Most insertions in dynamic array insertion operations cost \( O(1) \), but when the array is expanded, the insertion cost is \( O(n) \).

The aggregation method obtains the amortized cost by analyzing the total cost of all insertion operations and dividing by the number of insertions.

---

## II. Accounting Method

**Rationale:**

- Assign an Amortized Cost to each operation;

- The excess cost is saved as **Balance (Credit)** and used to pay for subsequent, more expensive operations;
- Guaranteed total amortized cost ≥ actual total cost.
**Strategy:**
- **Cheap operation:** Amortized cost > actual cost, with the excess as a balance;
- **Expensive operation:** Amortized cost < actual cost, subsidized by previously accumulated balances.

**Features:**

- Finer control of cost allocation;

- Suitable for scenarios where some operations are extremely costly, but can be "subsidized" by other operations.
**Examples:**
Allocate $3 per insertion in the dynamic array as amortized cost:
- The actual insertion only cost $1;
- The remaining $2 is set aside as a balance for future expansion operations.

---

## III. Potential Method (Potential Method)

**Rationale:**

Define a **Potential Function** \( \Phi \) for the data structure that represents the "pre-stored resources" in the current state.
The amortized cost of the first \( i \ ) operation is:

$$
\hat{c}_i = c_i + \Phi(D_i) - \Phi(D_{i-1})
$$
Among them:
- \( c_i \ ): the actual cost of the \( i \ ) operation;
- \( \Phi(D_i) \): potential energy after the \(i \) th operation;
- \( \Phi(D_{i-1}) \): potential energy before operation;

- \( \hat{c}_i \): amortized cost.

**Explanation: **

- If the potential energy increases, it means that this operation prepares for the follow-up;

- If the potential energy decreases, it means that the previously accumulated resources were used up.
**Features:**

- Mathematics is formalized and expressed flexibly and rigorously;

- Ideal for analyzing data structures with frequent dynamic state changes.

---

| Accounting Method | Accounting Method | per operation             | yes                                                 | with balance mechanism, suitable for individual operation is more expensive |

| Potential Method | Potential Method | Every Operation | Yes | Modeling with Potential Functions, suitable for complex state data structures |

# heap-like notation for a binary tree

A **Heap-like notation for a binary tree** is a way to represent a **Complete Binary Tree** by an array (usually starting at subscript 1), which is widely used in heap structures, but can also be used for sequential storage representation of other binary trees.

---

## I. Basic ideas

In a **heap-like notation**, the nodes of a binary tree are stored in an array in **Level-order traversal** order, numbered starting at **1** (or sometimes 0, but a typical heap is more intuitive starting at 1).

For a node numbered `i`, the relationship is as follows:

| Relationships        | Formulas  | Meanings                                                     |
| -------------------- | --------- | ------------------------------------------------------------ |
| **Parent**           | ⌊i / 2⌋   | The parent subscript of the i-th node. For example, if i=4, the parent is 2. |
| **Left child node**  | 2 × i     | The left child subscript of the i-th node. For example, if i=2, the left child is 4. |
| **Right child node** | 2 × i + 1 | The right child subscript of the i-th node. For example, if i=2, the right child is 5. |

---

## II. Examples

Consider the following binary tree (with the largest heap as an example):

``
50
/ \
30 20
/ \ /
10 15 18
``

Stored as an array (starting at subscript 1) with heap-like notation:

| subscript (i) | numeric |
| ------------- | ------- |
| 1             | 50      |
| 2             | 30      |
| 3             | 20      |
| 4             | 10      |
| 5             | 15      |
| 6             | 18      |

Relationship Validation:

- The left child of node 1 is at subscript 2 (30) and the right child is at subscript 3 (20)

- The left child of node 2 is at subscript 4 (10) and the right child is at subscript 5 (15)

- The left child of node 3 is at subscript 6 (18)

---

## III. Advantages and limitations

### ✅ Advantages

- **No need for pointers**, implement tree structures with arrays

- For **complete binary trees** such as heaps

- **Parent-child relationships are computationally simple**, O(1) Access

### ❌ Limitations

- Wasted array space if used for **non-complete binary trees**

- Unsuitable for representing highly unbalanced trees (e.g., chained structures)

---

## IV. Application scenarios

- **Heap implementation**

- Maximum Heap / Minimum Heap

- priority queue

- **Heap Sort**

- **Segment Tree**

- **Fenwick Tree **

- for certain memory compact structures such as heap structures in graph algorithms (e.g. Dijkstra)

---

## Min-Max Heap

### What is Min-Max Heap?

Min-Max Heap is an array-based Complete Binary Tree that divides nodes into **Min layers** and **Max layers** according to their depth, as follows:

- **The root node is at the Min level (depth 0)**, indicating the minimum value of the whole tree.

- ** Its child is at the Max level (depth 1)**, indicating the subtree maximum.

- **grandchild node back to the Min level (depth 2)**, denoting the subtree minimum.

- So alternately.

That is to say:

- **Even layers (0, 2, 4, ...) are Min layers** that maintain the minimum value;

- **Odd layers (1, 3, 5, ...) are Max layers** that maintain the maximum value.

### Operation

| operations    | time complexity | description                                  |
| ------------- | --------------- | -------------------------------------------- |
| `findMin()`   | O(1)            | root node                                    |
| `findMax()`   | O(1)            | greater of two children of root              |
| `insert(x)`   | O(log n)        | inserts and "floats" to the correct position |
| `deleteMin()` | O(log n)        | delete root node and "sink"                  |
| `deleteMax()` | O(log n)        | delete max node and "sink"                   |

#### 1. Node Hierarchy Determination

Given a node's subscript `i` (starting from 1) in an array with layers:

`level(i) = ⌊log₂(i)⌋'

Determines if it is at the Min level:

`is_min_level(i) = level(i) % 2 == 0`

#### 2. Insertion operations

- Inserts the new element into the end of the array;

- Determine which layer (Min or Max) it is on;

- Compare and float up to the correct position, following the rules of Min Heap or Max Heap, respectively.

#### 3. Delete operations (lookups are similar, except that there is no delete operation)

##### `deleteMin()`

- Delete the root node (subscript 1);

- Replace with the last element of the array;

- Sinks downward, maintaining the Min-Max Heap nature.

##### `deleteMax()`

- Find the larger of the two children (subscripts 2 and 3) of the root;

- Delete it and replace it with the last element;

- Downward "sinking".

## Dynamic sequential statistics

### Common operations

1. **OS-SELECT(i, S)**.

- This operation returns the i-th smallest element in the dynamic set S.

- For example, if i=3, then the operation will return the third smallest element in the set.

2. **OS-RANK(x, S)**.

- This operation returns the rank (i.e., the position) of the element x after it has been sorted in the set S.

- The rank is the position of the element in the sorted set, e.g., if x is the second smallest element in the set, then its rank is 2.

### Ideas for enhancing data structures

- **Use of Mangroves**.

- A red-black tree is a self-balancing binary lookup tree that ensures that the height of the tree is roughly O(logn), where n is the number of nodes in the tree.

- This property of the red-black tree allows it to maintain good performance in insertion, deletion and lookup operations.

- **Store subtree size**.
- In each node, in addition to storing the key value (key), the subtree size (size) of that node is also stored.

- Subtree size is the number of nodes in the subtree rooted at this node.

- Storing the subtree size allows the rank of an element to be quickly computed or the i-th smallest element to be found when performing sequential statistical operations.

### Node representation

- A representation of the node is shown in the slide, which contains two main parts:

- **key**: The key value of the node, i.e. the actual data stored in the node.

- **size**: The size of the subtree rooted at this node.

With this enhancement, dynamic sequential statistics operations can be accomplished in logarithmic time, which is useful for application scenarios where such operations need to be performed frequently.

# Von Neumann Architecture (**Von Neumann Architecture**)

The **Von Neumann Architecture** is a model of the infrastructure of modern computer systems, proposed by mathematician John von Neumann (**John von Neumann**) in 1945. It defines the basic components of a computer and how it works. The architecture is explained in **detail** below, with the English terms of the relevant terms labeled.

## II. Core Ideas of the von Neumann System ##

### 1. Stored Program Control (**Stored Program Concept**)

Programs and data** are uniformly stored** in the main memory, which the computer reads and executes one by one in the order of instructions.

> Prior to this, early computers required manual wiring or control panel changes to "change programs", which was highly inefficient.

### 2. Sequential Instruction Execution (**Sequential Instruction Execution**)

The CPU reads instructions from memory **in order** and automatically jumps to the next instruction after executing one, unless it encounters a jump instruction (such as `goto` or `if-else`).

### 3. Data and instructions are stored in the same memory (**Unified Memory for Data and Instructions**)

Program instructions and data** share the same storage area**, which both simplifies the hardware structure and creates potential problems (e.g., program code can be modified, protection mechanisms are needed).

------

## III. Workflow: Instruction Cycle (**Instruction Cycle**)

The execution of an instruction usually consists of the following steps:

1. **Fetch**: Fetch the next instruction from memory (at the address specified by the program counter PC).
2. **Decode**: The controller analyzes the instruction to determine the operation to be performed and the operand position.
3. **Execute**: An operator or other unit performs an instruction operation.
4. **Store/Writeback**: Write the result back to memory or registers.
5. **Update Program Counter (PC)**: points to the address of the next instruction.

This process is called the **Fetch-Decode-Execute Cycle**.

## V. Strengths and limitations

### Pros:

- Simplified computer design structure for easy hardware implementation
- Unified memory model that allows programs to read and write data flexibly
- Become the infrastructure for the development of modern computers

### Limitations (also known as the "von Neumann Bottleneck" **Von Neumann Bottleneck**):

- **Instructions and data share the same memory bus**, resulting in limited read speeds (instructions and data cannot be read at the same time)
- Instructions are executed sequentially, not suitable for parallel processing tasks
- Cache misses can seriously slow down execution

Although today's computer architectures are still based on von Neumann, many optimization techniques have been introduced in practice, for example:

- **Harvard Architecture**: instructions and data are stored and processed separately to alleviate bottlenecks
- **Pipelining**: multiple instruction stages processed in parallel to increase throughput rates
- **Cache Memory**: small cache inside the CPU to reduce access latency
